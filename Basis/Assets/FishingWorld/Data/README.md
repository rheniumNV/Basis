# 釣りワールドのデータ

ここのファイルを編集したら、Unity のメニュー **Basis > Tools > Fishing World > Build Scene** でシーンを作り直してください（魚のモデル・図鑑ボードの行・スクリプトの値がまとめて作り直されます）。その後で BEE をビルドします。

## fish.json — 釣れる魚

全体の設定:

| 項目 | 意味 |
|---|---|
| `rewardSizeBonus` | サイズによる報酬ボーナス。最小サイズで基本値×1、最大サイズで基本値×(1+この値)。1.0 なら最大で2倍 |
| `crownGoldPercent` | 図鑑の金の王冠：最大サイズが「大きさの上位◯%」、最小サイズが「小ささの上位◯%」に入ると付く |
| `crownSilverPercent` | 銀の王冠：同じく上位◯%（金に届かなかったとき） |

魚ごと（`fish` の中の1ブロックが1匹。並び順が図鑑ボードの並び順）:

| 項目 | 意味 |
|---|---|
| `name` | 魚の名前。**サーバーにはこの名前で記録されます。名前を変えると、変える前の記録とは別の魚扱いになります** |
| `nameEn` | 英語の名前（英語表示のときに使う。サーバーの記録には使わないので、変えても記録は分かれない） |
| `weight` | 出やすさ（全魚の合計に対する割合で抽選。例：35 と 25 なら 35:25 の比） |
| `minCm` / `maxCm` | サイズの範囲（cm）。大きいほど出にくい（小さめに偏る）抽選です |
| `rare` | `true` で釣れたときキラキラし、最近の釣果に ★ が付く |
| `baseExp` / `baseMoney` | 釣ったときにサーバーへ送る経験値とお金の基本値（サイズで増える。上の `rewardSizeBonus`） |
| `model.type` | `fish`（魚）か `boot`（長靴） |
| `model.lengthCm` | モデルの基準の長さ。実際の表示サイズは釣れたサイズに合わせて拡大縮小 |
| `model.width` / `model.height` | 胴の幅と高さ（m） |
| `model.body` / `belly` / `fin` | 胴・腹・ヒレの色（16進カラー、`#` なし） |
| `model.patch` | 背中のまだら模様の色（空なら無し） |
| `model.stripe` | 横の帯の色（空なら無し） |
| `model.whiskers` | `true` でヒゲ（ナマズ風） |

王冠の判定は、サイズの抽選の仕組み（範囲内で小さめに偏る）から「そのサイズ以上／以下が出る確率」を計算して決めています。`minCm` / `maxCm` を変えると判定も自動で変わります。

## strings.json — 看板やボードの文言

`key` ごとに日本語（`ja`）と英語（`en`）を書きます。`
` は改行、`{0}` はそこに数値などが入る場所です。言語は各プレイヤーがスタート地点脇の看板で切り替えられ、最初は OS の言語が日本語なら日本語、それ以外なら英語になります。`key` は変えないでください（スクリプトとビルダーがこの名前で探します）。

## backend.json — 記録サーバー

| 項目 | 意味 |
|---|---|
| `apiBaseUrl` | 釣りAPIのURL（例 `https://fishing.example.com`、末尾の `/` なし）。空ならサーバーを使わない（ランキングは空、図鑑は今回の記録だけ） |
| `rankingLimit` | ランキングの表示人数 |
| `rankingRefreshSeconds` | ランキングを読み直す間隔（秒） |
| `editorTestUserId` | Unity エディタで試すとき専用のユーザーID（エディタはオフラインで Basis のIDが無いため）。ビルドしたワールドでは使われません |

## 注意

- 魚データ・効果音・BGM・見た目は AI が作ったものを含むため、Basis 本体のリポジトリ（AI.md）には入れられません。
